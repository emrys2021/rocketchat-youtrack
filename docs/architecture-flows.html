路线 A — Outgoing Webhook + YouTrack MCP
1
用户在 Rocket.Chat 频道发消息，消息中包含触发词 @youtrack-bot（触发词在 Outgoing Webhook 配置中定义）
Rocket.Chat 仅在消息包含配置的触发词时才转发；不支持私信（DM）
2
Rocket.Chat 向后端 POST /webhooks/rocket，请求体包含消息内容、房间、发送者，以及 token 字段用于身份校验
HTTP POST，后端通过 ROCKET_WEBHOOK_TOKEN 比对验证来源合法性
3
Bot 后端（server.js）校验 token；过滤 bot 自身消息、系统消息、auto-reply；loop guard 滑动窗口计数，防止 60 秒内同一房间超过 4 次响应
4
Bot → LLM：将用户消息 + MCP 工具列表（search_issues 等）发给 LLM，LLM 决定调用哪些工具及参数
最多 MCP_MAX_TOOL_ROUNDS 轮工具调用（默认 10 轮）
5
Bot → YouTrack MCP：调 search_issues；后端自动对 top-N 候选 issue 补充调 get_issue、get_issue_comments，结果追加给 LLM
6
Bot → YouTrack REST：对每个候选 issue 调 GET /api/issues/{id}/timeTracking/workItems，获取工时记录作为额外证据
7
LLM 综合所有工具结果，按系统提示用简体中文输出最终回答，分段列出描述、评论、工时证据
8
Bot → Rocket.Chat：调 chat.sendMessage REST API，以 bot 账号回复到原房间/线程；超长消息自动分段（默认 3500 字/段）
路线 B — Bot-login Realtime + YouTrack MCP
1
Bot 后端（bot-runner.js）启动时主动建立 WebSocket 连接，完成 DDP 握手，用 ROCKET_BOT_USERNAME + sha256(ROCKET_BOT_PASSWORD) 登录
DDP 支持 username/password 或 login({ resume })；resume token 可以是 PAT；断线后指数退避重连（最长 60s）
2
登录成功并通过 /api/v1/me 身份确认后，默认订阅 notification + rooms-changed；notification 漏消息时切到 stream-room-messages/__my_messages__
私信无需触发词；频道消息需包含 @youtrack-bot
3
用户发私信或频道 @youtrack-bot，Rocket.Chat 通过 WebSocket 推送 stream-notify-user changed 事件
4
Bot 后端 解析 notification 或 fallback 消息，过滤：bot 自身消息（DDP userId + REST userId 双重比对）、系统消息（isSystem）、auto-reply（isAutoReplyText 正则匹配）；message dedupe 去重；loop guard 计数
5
先向原房间/线程发进度消息「收到，正在处理，请稍候…」，随后异步调 agent.answer()
可用 ROCKET_POST_PROGRESS=false 关闭进度消息
6
Bot → LLM + MCP + YouTrack REST：与路线 A 步骤 4–6 完全相同，走同一套 agent.answer() 逻辑
7
Bot → Rocket.Chat：用 PAT（ROCKET_REST_PAT）调 chat.sendMessage REST API 回复；PAT 不过期，比登录 token 更稳定
路线 C — Bot-login Realtime + 纯 LLM（待实现）
1
Bot 后端 WebSocket 登录 + 订阅与路线 B 完全相同；无需额外配置 MCP 或 YouTrack
只需配置 LLM_API_URL、ROCKET_BOT_USERNAME、ROCKET_BOT_PASSWORD
2
用户发私信或频道 @youtrack-bot，可以问任意问题，不限于 YouTrack issue 查询
可选路由规则：消息含 /yt 前缀走路线 B，否则走路线 C
3
Rocket.Chat WS 推送 → Bot 后端同样做 auto-reply 过滤、去重、loop guard，流程与路线 B 步骤 3–4 相同
4
Bot → LLM：不传 tools 列表，直接调 POST /v1/chat/completions，系统提示改为通用助手角色，单轮请求即可得到回答
需新增 agent.chat(question) 方法，约 20 行代码
5
LLM 直接输出回答，无工具调用轮次，延迟比路线 A/B 低（省去 MCP 多轮 RTT）
6
Bot → Rocket.Chat：chat.sendMessage REST 回复，与路线 B 步骤 7 相同
★
可选共存路由：@youtrack-bot /yt 问题 走路线 B（YouTrack 检索）；@youtrack-bot 问题 或私信走路线 C（通用聊天）
路由逻辑在 bot-runner.js 的 handleIncoming() 中按前缀分支即可
